## 已阅读和理解的代码

目前已经重点看过：

1. `tabular/imputation/GAIN_modules.py`
2. `tabular/imputation/GAIN.py`

对 GAIN 当前实现的理解：

1. `GAIN.py` 负责算法类封装，继承 `BaseImputer`。
2. `GAIN.__init__()` 保存超参数，例如 `batch_size`、`hint_rate`、`alpha`、`epoch`、`device`。
3. `GAIN.train(data, missing_mask)` 负责：
   - 根据输入数据和 mask 准备训练数据。
   - 做 min-max normalization。
   - 初始化 `GainGenerator` 和 `GainDiscriminator`。
   - 调用 `GAIN_modules.py` 里的训练循环。
   - 保存 checkpoint。
4. `GAIN.predict(data)` 负责：
   - 检查模型是否训练过。
   - 使用训练时保存的 normalization 参数处理输入。
   - 用生成器补全缺失值。
   - 保留观测值，只替换缺失位置。
   - 反归一化并返回补全后的数据。
5. `GAIN_modules.py` 负责底层实现：
   - `GainGenerator`
   - `GainDiscriminator`
   - normalization / renormalization
   - noise 和 hint mask 采样
   - `train_gain_algorithm(...)` 训练循环

这个结构后续可以作为 FATE / DARN 接入的主要模板。

## 已修复的问题

### 1. `dataprep` 导入路径问题

最开始运行：

```powershell
python examples/imputation.py
```

出现：

```text
ModuleNotFoundError: No module named 'dataprep'
```

原因是项目目录名是 `DataPrep`，但代码里使用的是：

```python
from dataprep.tabular.imputation.GAIN import GAIN
```

在当前运行方式下，Python 无法自动把 `D:\DataPrep` 识别成小写包名 `dataprep`。

已在 `examples/imputation.py` 中加入包名注册逻辑，使示例脚本可以正确导入 `dataprep`。

用于在测试中统一注册 `dataprep` 包名。

## 当前项目状态判断

当前 imputation 模块的基础链路已经比较清楚：

```text
data_missing + missing_mask
        ↓
model.train(...)
        ↓
model.predict(...)
        ↓
imputed_data
        ↓
model.estimate(ground_truth, imputed_data, missing_mask)
```

这说明后续 FATE / DARN 接入时，应该尽量遵守现有风格：

```text
FATE.py
FATE_modules.py
DARN.py
DARN_modules.py
```

其中：

1. `FATE.py` / `DARN.py` 负责类封装、超参数、`train()`、`predict()`。
2. `FATE_modules.py` / `DARN_modules.py` 负责网络结构、工具函数、loss 和训练循环。
3. 两个算法都应继承 `BaseImputer`。
4. 输入 mask 约定应保持为 `1 = observed`，`0 = missing`。
5. 输出应保持为与输入同 shape 的 `np.ndarray`，且不包含 NaN。
