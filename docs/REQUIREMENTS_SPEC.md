# DataPrep 需求文档

## 1. 文档目的

本文档说明 `DataPrep` 软件当前已经实现的功能、目标用户、输入输出、运行边界，以及后续把 `FATE` 和 `DARN` 整合进 `imputation` 模块时应满足的业务要求。

## 2. 软件定位

`DataPrep` 是一个面向表格数据治理的数据准备工具。它覆盖三类常见问题：

1. 缺失值补全
2. 错误/异常检测
3. 脏数据修复

当前仓库同时提供两种使用方式：

1. Python 类库方式
2. Web 控制台方式

## 3. 目标用户

主要用户包括：

1. 需要处理表格缺失值、错误值的研究人员或工程人员
2. 希望通过图形界面运行算法的非开发用户
3. 需要在现有框架中继续集成新算法的开发者

## 4. 业务问题定义

### 4.1 缺失值补全

输入是一张包含空值的表，以及一张同形状的缺失掩码矩阵。

- 数据表中缺失值通常表现为 `NaN`
- 掩码矩阵中 `1` 表示该单元格原本有值，`0` 表示该单元格原本缺失

系统目标是输出一张已经补全的完整表，并在已知真值的实验场景下给出误差指标。

### 4.2 错误检测

输入是一张可能包含脏数据的表。

系统目标是找出哪些单元格可疑，并输出布尔矩阵：

- `True` 表示该位置被判定为错误
- `False` 表示该位置被判定为正常

### 4.3 数据修复

输入包括：

1. 脏数据表
2. 错误位置矩阵
3. 干净真值表

系统目标是在已知错误位置的前提下，尽量把错误值修复成正确值。

## 5. 当前功能需求

### 5.1 通用功能

系统需要支持：

1. 从 CSV 读取数据
2. 在 Python 中直接调用算法类
3. 在 Web 界面中配置参数并运行任务
4. 显示实时日志
5. 输出评估指标
6. 预览处理后的结果
7. 导出结果 CSV

### 5.2 缺失值补全功能需求

当前必须支持以下算法：

1. `GAIN`
2. `VAEGAIN`
3. `SCIS`

当前必须支持以下基线对比：

1. `BayesianRidge` 迭代补全
2. `RandomForestRegressor` 迭代补全

补全模块必须满足：

1. 统一输入 `data_missing` 和 `missing_mask`
2. 输出与输入同形状的二维数组
3. 支持训练后立即预测
4. 在真值存在时计算 `MSE`、`RMSE` 和 `MAE`

### 5.3 错误检测功能需求

当前必须支持：

1. `ZeroED`
2. `Isolation Forest`
3. `LOF`

检测模块必须满足：

1. 输出逐单元格错误掩码
2. 支持 Precision、Recall、F1 评估
3. 支持按列训练和推理

### 5.4 数据修复功能需求

当前必须支持：

1. `ZeroEC`
2. `Mode` 基线
3. `KNN` 基线

修复模块必须满足：

1. 只在检测矩阵标记为错误的位置上修复
2. 输出与原表结构一致的修复后数据
3. 支持 Precision、Recall、F1 和 EDR 评估

## 6. 非功能需求

### 6.1 易用性

1. 非机器学习背景用户应能通过文档理解基本运行逻辑
2. Web 控制台应支持直接配置路径和超参数
3. 算法执行过程应可见

### 6.2 可扩展性

1. 新算法应尽量遵守现有抽象基类接口
2. `imputation`、`detection`、`correction` 三类任务应保持结构一致
3. 新增算法应尽量少改前端和调度逻辑

### 6.3 可维护性

1. 核心算法入口与训练细节应分层组织
2. 文档中应说明重要代码位置
3. 测试应至少覆盖关键训练和推理流程

### 6.4 性能与资源

1. 所有算法应支持 CPU 运行
2. 深度学习算法在 GPU 上应能获得更高速度
3. LLM/Embedding 相关模块允许依赖外部模型服务或本地模型

## 7. 软件输入输出要求

### 7.1 输入格式

支持的主要输入格式：

1. CSV
2. Pandas DataFrame
3. NumPy ndarray

### 7.2 输出格式

支持的主要输出格式：

1. NumPy ndarray
2. Pandas DataFrame
3. CSV 文件
4. Web 端结果表格和图表

## 8. 环境需求

### 8.1 软件环境

至少需要：

1. Python 3.10
2. PyTorch 2.2 左右版本
3. FastAPI
4. Uvicorn
5. Pandas
6. NumPy
7. scikit-learn

按当前代码，若启用 `ZeroED` / `ZeroEC`，还需要：

1. LangChain 相关依赖
2. sentence-transformers 或 fast_sentence_transformers
3. FAISS
4. 可访问的 LLM API，或本地兼容 OpenAI 接口的模型服务

### 8.2 硬件环境

最低可运行环境：

1. CPU 4 核
2. 内存 8GB
3. 无 GPU

推荐环境：

1. CPU 8 核以上
2. 内存 16GB 以上
3. NVIDIA GPU，显存 8GB 以上

LLM 修复任务的推荐环境更高，尤其在使用本地 embedding 或本地大模型时。

## 9. FATE / DARN 后续需求

把 `papers` 下的 `FATE_SIGIR25` 和 `DARN_VLDB25` 整合进 `imputation` 模块时，建议满足以下要求：

1. 继续遵守 `BaseImputer` 接口
2. 统一输入为缺失数据和掩码
3. 统一输出为补全后的完整表
4. 先做单机版补全适配，不直接搬运论文中的完整分类/联邦训练主流程
5. 在文档中明确说明“论文原始任务”和“本项目适配任务”的区别

## 10. 验收标准

当前软件层面的验收可以按以下标准执行：

1. 能成功启动 Web 后端
2. `index.html` 可以连接后端
3. 三类任务至少各有一个可运行示例
4. 现有补全算法可输出数值结果和评估指标
5. 现有检测和修复算法可输出结果矩阵和评估指标
6. 文档能够帮助非机器学习背景用户理解系统用途、代码位置和运行方式
